# API Freeze Delta Reconciliation

The API-reduction pass was meant to shrink the surface, yet the public API
freeze grew from 3,102 symbols to 3,180. This document reconciles that growth:
it walks the difference between the tiering decisions in `api-tiering.json` and
the live freeze in `test/testdata/public_api/stable_public_api.json`, symbol by
symbol, so the release can tag a surface whose every name is accounted for.

The exhaustive rows live in `api-freeze-delta.json`, regenerated by the
adjacent `generate_api_freeze_delta.py`. The generator **fails** rather than
emitting an artifact when any symbol on either side is unclassified, so the
delta cannot grow silently. `TestPublicAPIFreezeDeltaIsReconciled` pins both
inputs by hash and re-checks every row against them.

## Result

Both directions are fully accounted for; the residue is empty.

| Direction | Count |
| --------- | ----- |
| Baseline  | 3,102 |
| Removed   | 402   |
| Added     | 480   |
| Freeze    | 3,180 |

The two tiering decisions hold:

- All **19 `delete` rows are gone** from the freeze — the Python-style
  introspection surface (`Setp`, `Getp`, `GetpAll`, `Findobj`, `FindobjType`,
  `PropertyBag` and its six implementations), the four `*Units` methods, and
  `render.CapabilityBridgeReporter`.
- The single **`demote` row landed exactly where it was sent**:
  `render.RendererModeReporter` is gone from `render` and present in `backends`.

## Why a reduction pass grew the count

Four causes, in descending size. Only the last is a genuine surface increase.

**1. The audit counts names, not fields (73 symbols).** Every category that
trades struct fields for named types is invisible on the way down and counted on
the way up. The `typed-enum`, `options-model`, `optional-package`,
`encapsulation-reader`, `figure-output`, and `shared-helper` rows are all this
shape. The pass deleted 205 variadic option tails and 408 pointer-to-primitive
fields; the audit counted none of those removals, but it counts the
`optional.Value[T]` constructors and folded value types that replaced them. This
is the effect the reduction pass predicted, and it is the single largest
contributor.

**2. The baseline collector had narrower coverage than the final one (30
symbols).** The `audit-scope` rows are API that already existed and was never
classified, because the pre-break collector skipped it:

- `animation`'s FFmpeg writer sits behind `//go:build ffmpeg` and predates
  the reduction pass by seven weeks. The final collector reads every non-test
  source file regardless of build constraints, so eight names appeared.
- `backends/skia` contributed 21. The final collector merges the
  unavailable-backend stub type with its `skiacgo`/`skiagpu` implementation, so
  the native draw methods and the GPU accessors (`FlushGPU`, `GPU`,
  `Surface`, `SampleCount`, …) are now visible. The GPU tier closed on the
  same day the baseline was taken.

These are a **measurement change, not an API change**. They also mean the
tiering artifact never got to decide on them, which is worth knowing before
the release tags the surface.

**3. The package split forced helpers open (19 symbols).** `plot3d`, `widgets`,
and `ticker` live outside `core` and need to draw text, order artists, resolve
rc state, and format ticks the way `core` does internally. Thirteen `core`
helpers (`DrawAlignedText`, `Axes.ResolvedRC`, `Collection.SetZ`,
`Scatter2D.PrototypePath`, the label pad and font-key accessors, …) and six
`ticker` helpers (`FormatTick`, `LabelFormatter`, `WithMajorContext`, the
`ScalarFormatter` methods) were exported purely to keep the split working. None
existed before the split — they were unexported or did not exist.

This is the one category worth revisiting: each is a real new public commitment
bought to pay for the package boundary, and a v1.0 surface would be smaller if
some moved to an `internal/` shim instead. Left as is for now — the split is
already shipped and the helpers are coherent — but flagged here so the release
tags them deliberately rather than by default.

**4. Two symbols from the contour unification**, which exported
`core.ResolveContourScalarMap` and `core.ContourFillScalarMap` so `plot3d` and
`core` could share one contour scalar-map resolver.

## Findings not previously recorded

Three differences were real and undocumented before this walk:

- **`core.WidgetArtist` and `core.Axes.AddWidget` were deleted, and the tiering
  artifact classified both `keep`.** The marker interface became the unexported
  `core.widgetArtist`, and `core.Axes.Add` now dispatches on it and routes
  widgets to the widget layer, so the separate entry point is redundant. The
  behavior is preserved and the design is better, but it is a user-facing break
  that neither the tiering record nor the migration notes mentioned. Both are
  now in `docs/matplotlib-migration-notes.md`.
- **`Renderer.Image` survives the freeze with a different meaning.** On
  `backends/agg`, `backends/gobasic`, and `backends/skia`, the draw method that
  held the name became `DrawImage`, and the buffer accessor formerly called
  `GetImage` took the vacated name. Symbol-id comparison shows no change; the
  signature did change. Any future audit that diffs ids alone will miss this
  class of break.
- **The freeze is 3,180, not the 3,176 recorded when the pass closed.** The
  contour unification added the two contour helpers; the affine-flattening fix
  added the `transform.AffineScale`/`IsAffineScale` pair. The roadmap and
  `docs/plans/changelog-draft.md` now say 3,180.

## Regenerating

```bash
python3 docs/plans/generate_api_freeze_delta.py
CGO_ENABLED=1 go test -tags freetype -run TestPublicAPIFreezeDeltaIsReconciled .
```

Run this after any change to the exported surface. The recorded hashes make the
test fail until the artifact is regenerated, and the generator fails until every
new or removed symbol has a decision — which is the point.
